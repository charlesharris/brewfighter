## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] SaveRepository inferred MainActor under the new default isolation**
- **Found during:** Task 3 (after adding SWIFT_DEFAULT_ACTOR_ISOLATION: MainActor)
- **Issue:** The unit test target (which does not use the new default) failed to compile: 17 "main actor-isolated ... in a synchronous nonisolated context" errors against SaveRepository, SaveLoadOutcome and SaveSource.
- **Fix:** Marked the three persistence types `nonisolated`, matching their existing `Sendable` design (save I/O should not be pinned to the main actor).
- **Files modified:** App/BrewFighter/Persistence/SaveRepository.swift
- **Verification:** Full suite passes (37 tests).
- **Commit:** 1b077d2

**2. [Rule 1 - Bug] Flaky touch-target overlap check on the detail screen**
- **Found during:** Task 3 (ChromeUITests first run after the settings change)
- **Issue:** `testDetailAndLedgerChrome` failed once: `detail.back` (y 8-52) "overlapped" `detail.attribute.sweetness` (y 20-64), a row scrolled partly beneath the fixed back button. The same test passed in the task 2 run and in isolation, so it depends on the scroll offset reached by the drag, not on the settings change. The back button sits outside the ScrollView, so this is clipping, not a real overlap (same class as the existing wizard chrome exemption).
- **Fix:** Added `detail.back` to the chrome ids that are exempt from pairwise overlap against scrolling content.
- **Files modified:** App/BrewFighterUITests/UITestSupport.swift
- **Verification:** Isolated rerun passed; subsequent full suite passed.
- **Commit:** 1b077d2
